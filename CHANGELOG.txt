App-side code changes
MediaPlayerView.swift — removed destructive logAssetDiagnostics pre-load that could poison asset keys before AVPlayerItem was created; replaced with non-destructive logAssetKeyStatus called from the item status observer
MediaResourceLoader.swift — explicit detection and clear error message when a ranged request gets 200 instead of 206 (this is what enabled us to diagnose the transient failure)
Key takeaway
The rapid back-and-forth between multiple media streams likely caused a transient anomaly (Cloudflare edge cache, Apache mod_cache_disk, or connection reuse artifact). The app now has better diagnostics to catch this if it recurs, and the preventive infra recommendations are documented for whenever you want to apply them.
